## 3. P0：用户已确认的问题

### F01 设置底部信息与按钮过近

参考：`Screenshot 2026-10-31 144351.png`。截图里“非官方社区插件”与下方两个按钮几乎贴住。这是间距问题，不是让按钮更小的理由。

要求与验收：

- 把说明文字、分隔、主要动作安排成清晰的底部区域。建议说明与按钮之间至少 12px、底部保留 16px；数值可随设计调整，但必须有明确呼吸感。
- 临时禁用 Q 版后，不应继续保留“切换角色形态”按钮，也不要空出一个失效按钮的位置。剧场入口保留。
- 设置正文可滚动，标题和关闭按钮始终可达；短窗口里不能截断最后一个操作。
- 中英文、系统缩放 100%/125%/150%、字号两端、明暗主题都不碰撞；按钮文字不被挤成难读的窄列。

### F02 设置到边缘后，角色继续钻到面板后面

参考：`Screenshot 2026-10-31 002402.png`。面板已被边界钳住，角色仍可移动，头和身体被面板覆盖。此前的“菜单跟随”测试只覆盖中间位置，不能证明边缘正确。

源码线索：`PetOverlay.tsx` 的 `panelTether` 只按角色位移累加面板位置，再单独钳制面板；`usability.ts` 的 `viewportPanel()` 使用固定尺寸估计。因此二者到边界后会分离。具体呈现以实测为准。

交互决策：**空间够时，面板与角色作为同一组布局；空间不足时，设置变成独立可读面板，并暂时停止角色游荡。** 不靠把角色提到面板上层来遮住控件。

要求与验收：

- 根据实测角色外接框和面板尺寸计算位置，优先在角色左右放置；接近边缘可换侧，不能每一帧左右抖动。
- 普通窗口空间足够时，角色头部和设置可同时看到，建议间隔 12–20px。拖拽、惯性、缩放、换姿态、面板展开/收起后重新满足约束。
- 设置交互期间暂停游荡；如果用户拖拽角色，在可放下整组的范围内移动。空间不够时切换到明确的独立面板模式，关闭后恢复角色的可见位置。
- 只有设置正文需要滚动；面板顶部、关闭按钮不能出屏。不得盖住宿主输入区的关键操作。
- 缩小窗口、改变系统缩放、切换长英文文案后，布局仍成立。不得靠写死 `356`、角色高度或旧图宽度作为唯一依据。
- 验收四个角、左右边缘、上下边缘：按住拖到极限后继续拖，再松手；在极限处改大小、切撒娇/眩晕、开关设置，均无遮头、失联、乱跳。

### F03 普通立绘到撒娇的视觉大小不一致

源码线索：目前每张图片用相同 CSS 高度，加统一 `max-width: 280px`、`object-fit: contain`。不同宽高比和透明留白可能使图像被不同约束缩小；这只是代码层面的原因候选，需结合素材实测，不能认定只改一个高度就能解决。

要求与验收：

- 建立统一角色展示框，为每张非 Q 版素材记录展示缩放和锚点。以**头部/脸部视觉尺寸及脚底基线**校准，不能只比较 PNG 画布高度。
- 不修改原图、不裁掉头发/尾巴/眩晕星星。允许通过展示元数据调整，素材权利与原始文件保持完整。
- `Maid / sajiao / Answering / baifan / getit / Think1–5 / Dizzy` 逐个对比；头部大小建议误差在约 5% 内，脚底/身体锚点不突跳。姿态本身不同无需强行几何重合。
- 桌宠与剧场分别校准；五档大小、普通/大屏剧场都要测。切图过渡不能造成重复人影、矩形光晕或可点击区域错位。
- 透明区域命中仍合理；展示变换必须与命中区域同步，不能只放大图片把实际拖拽目标留在原地。

### F05 恢复可发现的余额展示，区分“未读取”和“0”

余额展示仍在 `PetOverlay.tsx` 的工具栏里，但只在 `balancesKnown` 为 true 时渲染；工具栏隐藏、设置开启和账户页未打开时都可能让它看似消失。启动读取是独立集成问题，详见[余额数据交接](BALANCE_INTEGRATION.md)。

- 给余额一个稳定、轻量且容易找到的位置；不必常驻一整排工具按钮。充值和赠金分别标明，币种清楚。
- 根据正式数据状态显示“正在读取 / 暂未读取 / 读取失败 / 需要登录 / 已更新”等。没有数据用 `—`，不能伪造 `¥0.00`。
- 正式接入完成前，现有 DOM 模式应诚实提示“打开 DSH 账户设置以读取余额”，不能承诺启动自动获取。
- 数据过期可以保留最后成功值，但必须标注非实时；账户切换/登出要立即清除旧账户值。
- 低余额提示只针对已确认、未过期的可比币种数据；充值/赠金缺失、失败、未登录不能触发“快吃不起饭”。多币种不直接相加。
- 后端契约尚未接入时，可先用本地假数据做状态预览，但必须与运行数据隔离，不得把演示金额送进产品。

## 4. P1：建议的整体体验打磨

### F06 保留桌宠的存在感，降低菜单负担

建议常用入口维持设置、剧场与按需状态；安静、贴边、复制代码等可以按场景分组。不要为了“功能齐全”把所有按钮常驻在角色头顶。既有功能都必须有清晰入口，可重新组织，不能静默删掉。

- 统一毛玻璃、圆角、边线、阴影、间距和字体层级；明暗主题使用同一套语义变量，浅色选中态有明确对比。
- 保留用户喜欢的无框大小圆点：五档吸附滑条、小白点、中间加粗蓝点、无数字与框框。点可点击但不显露按钮盒子。
- 字号维持连续滑条，旁边显示实时数值；透明度和音量另行保持易懂。
- 面板与按钮不随角色缩放；文本可读优先于更窄更紧。
- 中英文切换只影响插件文案；明暗主题只影响插件，绝不切换 DSH 主题。
- 所有“Little Whale”产品称呼统一为“大肥鱼”；英文标题可写 `大肥鱼 Settings`，说明中用 `the companion`。用户自定义名字继续优先，不替换用户问答内容。
- 设置、菜单、滑条和图标按钮均可用键盘访问，有可见焦点和准确名称/选中状态。毛玻璃不足以保证对比，关闭模糊或不支持该效果时也应可读；不要动画化大面积高成本模糊。

### F07 人物音效可以重做，但先保证耐听和停止准确

当前 `experience.ts` 的 `PetAudio` 合成短音，`PetOverlay.tsx` 在流式输出/逐字展开期间通过循环调用。可以拆出独立音频模块并重新设计。

- 借鉴复古 RPG 的说话节奏，创作自己的音色；不提取或直接复用 Undertale 音频。不要求 TTS、配音或新增外部音频库。
- 说话反馈发生在**输出文字的过程中**；不能变成输出结束叫一声，也不能在网络长时间停顿时仍无限机械叫。应结合新文本到达/本地逐字揭示，有短停顿与句末呼吸。
- 轻柔中频、短包络、适度变化；避免持续高频、点击爆音和多个音源叠到过响。思考、回答、点击、顿悟之间有轻重之分。
- 默认静音；设置名仍叫“人物音效”。静音、音量为 0、停止生成、切会话、失焦/后台、卸载后及时停止，返回前台不补播积压声音。
- 点击跳过文字不补播一串音；长代码/日志不逐字符轰炸。自动播放和流式揭示共用一个播放调度，避免双重发声。
- 主观验收需真正听：耳机/扬声器，低/中音量，连续阅读至少 3 分钟；交付时记录听感验证。自动测试只证明生命周期和触发，不能证明“好听”。

### F08 剧场保留阅读逻辑，重新整理舞台空间

- 保留逐字显示、点一次补全再点下一页、上一段、自动、回顾、Hide、完整阅读、复制代码、快捷键和输入法保护。

## 5. 重做时必须保留的产品与工程约定

- 12 张 PNG 全保留、Base64 内嵌、无外部图片/音频依赖。暂停 Q 版不等于素材数减为 11。
- 推理随机 Think1–5/顿悟，回答期间用 Answering，饭图在输出结束或游荡后出现；交互结束正确回到当前模型状态，不能让撒娇/眩晕计时器覆盖流式回答。
- 读屏淡化仍可点，鼠标进入角色可恢复；只有按住 Alt 的显式穿透可暂停命中。设置交互不能被淡化破坏。
- 摸头、眩晕、有限拖拽惯性、贴边、安静模式、可关闭提醒、自定义名字、可选通知和 Doctor 都是既有能力，不默默删去。
- 音效默认关闭；通知默认关闭且主动开启时才请求权限；偏好只存本地，聊天历史只读已加载消息，不持久化、不发往额外服务。
- 不把字符数冒充 tokens/s；无数据不编造余额、今日消耗或预计费用。
- 宿主输入、中文输入法和草稿保留不能回归。不能遍历找到任意按钮就当成“发送”。

## 6. 代码地图与构建陷阱

- `src/client/PetOverlay.tsx`：主要界面、位置、菜单、阅读和音频调度；当前偏大，可拆组件。
- `SettingsPanel.tsx`、`DialogueContent.tsx`、`LivingPuppet.tsx`：设置、文本/代码、人物展示。
- `PetOverlay.module.css`、`LivingPuppet.module.css`、`galgame.css`：当前有多层历史覆盖，重构时梳理而不是无限追加。
- `usability.ts`：面板位置、分页和诊断；`hitareas.ts`：开发脚本生成的近似透明命中区域。
- `state-machine.ts` / `types.ts`：模型/人物状态；`preferences.ts`：偏好读取和兼容；`index.ts`：DSH DOM 适配。
- `src/index.ts`：Cordis 宿主入口，目前没有余额服务。不要误以为它已经提供 API。
- **源码与构建产物是双入口，但不再手工维护两份 React 模板。** `build.js` 编译源码并内嵌到 `lib/client.js`；改源码后构建，不能只改生成包。
- 自定义打包不是通用模块打包器：会剥离部分 imports，并把函数/模块放入工厂作用域；CSS Module 在浏览器包中映射为普通类名。新增组件/模块必须注册到 `build.js`，检查符号、样式冲突和真实浏览器包；只通过 TypeScript 检查并不足够。
- 构建目前会尝试从作者桌面的表情文件夹同步同名原图；`assets/` 是仓库素材。不要误把本机不同版本原图自动覆盖当成设计变更。清理此机制属于构建跟进，可与 Codex 协调。
- `lib/` 已跟踪，修改功能后提交对应生成文件。`dist/` 与压缩包不进源码提交。不要手改旧发布说明，把本轮变更写进 Unreleased。
